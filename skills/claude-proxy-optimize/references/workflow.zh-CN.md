# 中文操作流程

本文件与 SKILL.md 的英文流程对应。向用户使用其选择的语言汇报。

## 发现环境与记录基线

确认操作系统、客户端、当前订阅、生成配置、运行内核、控制器、HTTP 代理端口、系统代理、TUN、DNS 劫持、浏览器安全 DNS。不得假设端口、用户名路径、服务名称、机场、节点地区。对照保存配置与运行中的控制器；界面开启 DNS 不代表 DNS 走代理，普通用户列出的监听也可能看不到特权内核。

诊断保存在本机，不打印或上传订阅链接、密码、UUID 凭证、控制器密钥、Cookie、API Key、完整配置或原始连接历史。`proxy_tool.py inspect --config <当前配置>` 使用字段白名单输出。仅在本地需要选择节点时加 `--show-names`；不要用会同时命中 `uuid`、token 的宽泛搜索输出配置。

修改前测试 Claude 网页/API 路由、一个普通海外网站、一个普通直连网站及用户报告的问题网站。记录浏览器具体错误，检查失败的子资源；首页 HTTP 200 不等于浏览器流程可用。分别检查 DNS 和 WebRTC；不得绕过浏览器证书警告。

## 决定修改范围

- 关闭 Wi-Fi 或 Mihomo 本地 IPv6，不能强制远端节点改用 IPv4。以访问 Claude 的实际出口为准；对本地 HTTP 代理使用 `curl -4` 只限制本地连接。
- 为 Claude 建手动专用组，复用现有节点，不改变日常总代理组。选择稳定、可用、地区合适的出口；IP 协议、信誉和连通性分别判断，不能根据节点标签认定出口国家。
- 默认补齐 Claude 核心域名后缀规则。共享监控/客服规则仅在用户需要对应功能时加入，并说明同服务的其他软件也受影响。避免 `sentry`、`sift`、`datadog` 全局关键词和全局 NTP 改道。
- 默认只调整 Claude 的 DNS 策略。若确实有通用 DNS 泄露，再单独配置代理内的加密 DNS，同时保留直连网站合适的直连加密 DNS。本地分域解析、VPN、`.local`、`.lan`、反向解析、fake-IP 例外与已有隧道规则必须保留。不能为让检测变绿而把所有国内/内网查询交给海外 DNS。
- Mihomo 的 `https://<解析器IP>/dns-query#<代理组>` 可明确指定 DNS 连接走代理；使用前核对当前官方语法。为节点域名配置独立的 `proxy-server-nameserver`，避免连接节点需要先通过该节点解析自身。可以使用 IP 地址形式的加密引导解析器，或保留已验证的引导配置。不得公开控制器或关闭证书校验。

## 生成方案、实施与恢复

用户只要求检查时不修改。用户授权优化后完成必要可逆修改，不另设无依据的确认步骤；遵守实际系统权限。不扩展到凭证/设备 ID 清理、账号轮换、时区伪装或远端服务器修改。

先在 Git 外创建权限受限的本地备份，记录订阅 ID、受影响的扩展/DNS 文件、代理组当前选择与回滚步骤。备份可能含密钥，不能上传。

```text
python proxy_tool.py plan --config <当前配置> --node <现有节点> --output <新的本地未跟踪目录>
```

命令生成代理组、规则和 DNS 策略三个覆写方案，不直接改网络。`--include-support` 加入共享服务。代理组同名时拒绝生成；换一个组名或审查并手动更新已有组。

把生成条目合并到当前订阅扩展，保留其他 prepend/append/delete、DNS 策略和代理组。Clash Verge 的全局/订阅 DNS 覆写可能覆盖扩展，必须修改实际生效的层。不要仅编辑每次重新生成的运行配置。有已安装的 Mihomo 内核时用 `mihomo -t -f <候选配置>` 校验，再通过客户端正常途径重新激活。候选配置也可能含密钥，不能提交到 Git。

经授权比较节点时，仅切换手动专用测试组：

```text
python proxy_tool.py probe --socket <发现的内核套接字> --proxy http://127.0.0.1:<端口> --group <手动组> --nodes <节点A> <节点B>
```

无 Unix 套接字的平台使用 `--controller http://127.0.0.1:<控制器端口>`。控制器密钥仅由 `MIHOMO_API_SECRET` 环境变量传入，不写命令参数或受跟踪文件。工具在 finally 中恢复并验证原节点。禁止并发比较；进程强制退出、内核关闭仍可能阻断恢复，因此事先记录并事后核对选择。比较短暂影响该组的新请求，不能借用日常总代理组。若需临时测试组，通过受支持的扩展建立，完成后仅撤销自己创建的测试内容。

`--risk` 会把测得的公网出口 IP 发送给 Net.Coffee，须先说明目的地并遵守用户授权；`--show-ips` 在本地输出出口 IP。默认只输出编号和每次运行加盐的出口标识，不输出节点名称和完整 IP。第三方分数不等于 Anthropic 内部风控，IPv6 信息可能不完整，单次请求时间不等于速度/RTT 基准。工具会恢复原节点，最终选择须另经客户端保存。

## 验收

1. 运行规则使 Claude 网页/API、认证和已授权的关联域名走专用组，其他网站仍按预期分流。
2. 访问 Claude 网页/API 的 `cdn-cgi/trace` 核对出口。此测试只验证路由，不证明登录/模型可用；不擅自发起付费 API 请求。
3. 实际加密 DNS 上游连接走对应组，直连 DNS 和内网仍可用。
4. 深度 DNS 检测相对基线改善，同时在用户实际浏览器验证普通海外/本地网站、报告的问题、必要登录/CDN 资源能正常显示。
5. 重新激活后配置和节点选择保持；以运行配置与 API 为准，不以保存提示为准。

若普通浏览退化，立即修正或回滚造成问题的 DNS/规则改动，保留用户同期改动。不能只因泄露检测通过就宣布完成。区分临时节点故障与已证实的配置缺陷。汇报修改、节点、实机验收、限制和私有备份位置，不承诺防封号，不声称本地标识清理能抹掉服务端记录。
